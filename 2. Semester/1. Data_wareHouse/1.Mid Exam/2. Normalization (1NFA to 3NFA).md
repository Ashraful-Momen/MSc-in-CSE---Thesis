# 🧠 1. KEY CONCEPTS (সব ধরনের Key বুঝে নাও)

## 🔑 1. Primary Key

👉 যেটা দিয়ে প্রতিটা row uniquely identify করা যায়

📌 Example:

```text
Student(ID, Name)
```

👉 Primary Key = `ID`

---

## 🔑 2. Candidate Key

👉 যেসব attribute দিয়ে uniquely row identify করা যায় (possible primary key)

📌 Example:

```text
Student(ID, Email, Phone)
```

👉 Candidate Keys:

* ID
* Email
* Phone

👉 এর মধ্যে যেটা choose করা হয় = Primary Key

---

## 🔑 3. Composite Key

👉 একাধিক column মিলে primary key হলে

📌 Example:

```text
(StudentID, CourseID)
```

👉 একা একা unique না, কিন্তু একসাথে unique

---

## 🔑 4. Foreign Key

👉 অন্য table এর primary key কে reference করে

📌 Example:

```text
Grade(StudentID)
```

👉 StudentID → Student table এর PK

---

## 🔑 5. Secondary Key

👉 যেটা search/indexing এর জন্য use হয়, কিন্তু unique না

📌 Example:

* Name
* Department

👉 এগুলো দিয়ে data search করা যায় but unique না

---

## 🔑 6. Non-Key Attribute

👉 Primary key ছাড়া বাকি সব column

📌 Example:

```text
Student(ID, Name, Dept)
```

👉 Non-key:

* Name
* Dept

# 🧱 2. NORMALIZATION PROCESS (STEP BY STEP)

---

# ❌ UNNORMALIZED TABLE (UNF)

```text id="unf1"
+----+---------+-------------------+----------+
| ID | Name    | Courses           | Grades   |
+----+---------+-------------------+----------+
| 1  | Alice   | Math, Science     | A, B     |
+----+---------+-------------------+----------+
```

## ❌ Problems:

* Multiple values in one cell
* Hard to update
* Redundancy

---

# 🟡 STEP 1 → 1NF (Atomic Value)

## Rule:

👉 এক cell এ একটাই value

---

```text id="nf1"
+----+---------+---------+-------+
| ID | Name    | Course  | Grade |
+----+---------+---------+-------+
| 1  | Alice   | Math    | A     |
| 1  | Alice   | Science | B     |
+----+---------+---------+-------+
```

## 💡 Key Idea:

👉 No multiple values in a cell

---

# 🟠 STEP 2 → 2NF (No Partial Dependency)

## Rule:

👉 Non-key attribute must depend on FULL primary key

---

### Problem Table:

```text
(StudentID, CourseID) → Name, Grade
```

---

```text id="nf2"
+-----------+----------+----------+-------+
| StudentID | CourseID | Name     | Grade |
+-----------+----------+----------+-------+
| 1         | 101      | Alice    | A     |
| 1         | 102      | Alice    | B     |
+-----------+----------+----------+-------+
```

---

## ❌ Problem:

* Name depends only on StudentID
* Not on full key (StudentID + CourseID)

👉 This is called:

# ❌ Partial Dependency

---

## ✅ FIX (2NF)

### 👤 Student Table

```text id="st2"
+-----------+-------+
| StudentID | Name  |
+-----------+-------+
| 1         | Alice |
+-----------+-------+
```

### 📘 Enrollment Table

```text id="en2"
+-----------+----------+-------+
| StudentID | CourseID | Grade |
+-----------+----------+-------+
| 1         | 101      | A     |
+-----------+----------+-------+
```

---

## 💡 2NF KEY IDEA:

👉 “সব non-key attribute full key এর উপর depend করবে”

---

# 🟢 STEP 3 → 3NF (No Transitive Dependency)

## Rule:

👉 Non-key attribute কখনো অন্য non-key attribute এর উপর depend করবে না

---

## ❌ Problem Table:

```text
StudentID → DeptID → DeptName
```

```text id="nf3bad"
+-----------+-------+--------+----------+
| StudentID | Name  | DeptID | DeptName |
+-----------+-------+--------+----------+
| 1         | Alice | D1     | CSE      |
+-----------+-------+--------+----------+
```

---

## ❌ Problem:

* StudentID → DeptID ✔️
* DeptID → DeptName ✔️

👉 Indirect dependency exists

---

## ❌ This is:

# Transitive Dependency

---

## ✅ FIX (3NF)

### 👤 Student Table

```text id="st3"
+-----------+-------+--------+
| StudentID | Name  | DeptID |
+-----------+-------+--------+
| 1         | Alice | D1     |
+-----------+-------+--------+
```

### 🏢 Department Table

```text id="dept3"
+--------+----------+
| DeptID | DeptName |
+--------+----------+
| D1     | CSE      |
+--------+----------+
```

---

## 💡 3NF KEY IDEA:

👉 “Non-key attribute অন্য non-key attribute এর উপর depend করবে না”

---

# 🔥 SUPER QUICK REVISION

## 🧱 Keys:

* Primary Key → unique ID
* Candidate Key → possible PKs
* Composite Key → multiple columns PK
* Foreign Key → relation between tables
* Secondary Key → search key
* Non-key → everything except PK

---

## 🧠 Normalization:

| Form | Rule                     |
| ---- | ------------------------ |
| 1NF  | No multi-value cells     |
| 2NF  | No partial dependency    |
| 3NF  | No transitive dependency |

---

# 🎯 ONE LINE MEMORY TRICK

👉 1NF = “Single value”
👉 2NF = “Full key dependency”
👉 3NF = “No indirect dependency”

---

# 💥 FINAL MIND MAP (SUPER IMPORTANT)

```text
UNF
 ↓
1NF → Atomic values
 ↓
2NF → Remove partial dependency
 ↓
3NF → Remove transitive dependency
```
